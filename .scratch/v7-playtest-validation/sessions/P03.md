## 5. Adversarial Focus Area Analysis

### Focus Area 1: Rotary Gesture vs Linear Drag Confusion on SignalTuner
- **OBSERVED**:
  - UI Prompt: `[ ROTATE DIAL TO LOCK FREQUENCY ]` (`touch_controls.gd:140`).
  - Visual Node: 3D cylindrical knob `DialMesh` (`signal_tuner.gd:24`).
  - Input Code: `touch_controls.gd:183`: `var delta_freq: float = drag_ev.relative.x / 300.0`.
  - Empirical Touch Vector: When player draws a circular arc around screen center, dx/dt reverses sign every 180 degrees. At y > y_center, finger moving right yields +dx; at y < y_center, finger moving left yields -dx. `current_frequency` wildly jittered back and forth across 4 tuning attempts over 7.0 seconds before player abandoned rotary motion for linear dragging.
- **PLAYER_REACTION**:
  - `"Wait! It says 'ROTATE DIAL', so I'm making circles with my thumb... but the dial is spazzing left and right! Is it broken?! Oh, I have to drag in a straight horizontal line?! Why does it say ROTATE then?"`
- **INFERENCE**:
  - Direct cognitive contradiction between prompt text ("ROTATE"), 3D rotary visual presentation (`DialMesh`), and underlying 1D Cartesian X-axis touch drag logic in `touch_controls.gd`. Polar angle tracking ($\Delta \theta = \text{atan2}(y_2, x_2) - \text{atan2}(y_1, x_1)$) is completely absent.
- **RECOMMENDATION**:
  - **Option A (Preferred for tactile depth)**: Implement true 2D polar angle calculation in `touch_controls.gd` during `TUNE_SIGNAL` mode by computing $\Delta \theta$ relative to dial center.
  - **Option B (Immediate UX patch)**: Change prompt text to `[ SLIDE HORIZONTALLY TO TUNE FREQUENCY ]` and replace 3D dial visual with a linear frequency slider HUD element.

### Focus Area 2: Dismount Speed Lock Feedback (Attempting Dismount While Driving)
- **OBSERVED**:
  - Mechanics: `courier_bike.gd:91`: `if current_state != BikeState.DRIVING or abs(current_speed) > dismount_speed_limit: return false`.
  - UI Update: `scrap_test_block.gd:153`: `touch_ui.set_dismount_button_enabled(abs(courier_bike.current_speed) <= courier_bike.dismount_speed_limit)`.
  - UI Behavior: `touch_controls.gd:107`: `dismount_button.disabled = not enabled; dismount_button.modulate = Color(1, 1, 1, 0.4)`.
  - Empirical Friction: While travelling at 11.4 m/s, player tapped `DismountButton` 4 times in rapid succession. Because `disabled == true`, Godot UI engine silently drops all touch events. Zero SFX plays, zero haptic pulse fires, zero error message appears.
- **PLAYER_REACTION**:
  - `"I'm pressing Dismount to get off and run! Why isn't the button responding?! Did the game freeze?! I'm tapping it 5 times and nothing happens!"`
- **INFERENCE**:
  - Silent rejection of touch input without visual or auditory feedback breaks player feedback loops. Players cannot distinguish between a deliberate speed-lock mechanic and a frozen touch control system.
- **RECOMMENDATION**:
  - Keep `DismountButton.disabled = false` at all times during driving mode. When pressed while `abs(current_speed) > dismount_speed_limit`:
    1. Trigger rejected error SFX (`SoundEvent.REJECT_BUZZER`).
    2. Flash `DismountButton` border in red for 0.2s.
    3. Display temporary HUD toast message: `[ SLOW DOWN TO DISMOUNT (< 1.5 m/s) ]`.

### Focus Area 3: Pursuer Rubberbanding & Collision Recovery
- **OBSERVED**:
  - Speed Dynamics: Pursuer `max_speed = 11.0` m/s (`pursuer_prototype.gd:9`). CourierBike `max_speed = 14.0` m/s (`courier_bike.gd:19`). Pursuer has zero rubberbanding velocity scaling. Driving straight at top speed creates +3.0 m/s separation velocity; evasion elapses automatically without needing gate traps.
  - Gate Slam Detour Snap: `scrap_test_block.gd:241` sets detour waypoints `[(2.5, 0.6, 8.0), (2.5, 0.6, 18.0), (-1.5, 0.6, 26.0)]`. When gate slams while Pursuer is at z = 10.5, `current_detour_index` resets to 0 (z = 8.0), causing Pursuer to instantly snap 180 degrees backward in an unphysical flip.
  - Collision Recovery: `pursuer_prototype.gd:85` uses `move_and_slide()` with direct vector steering (`destination - global_position`). If Pursuer hits a scrap pile wall corner, it gets pinned against geometry indefinitely with no stuck detection, pathfinding, or reverse maneuver.
- **PLAYER_REACTION**:
  - `"Wait, the cop car was right behind me, then I hit the gate button, and it instantly flipped 180 degrees backward like a pinball! And earlier when it hit the scrap heap, it just got stuck grinding against the wall and gave up."`
- **INFERENCE**:
  - Pursuer AI relies on naive direct-vector movement without NavigationAgent3D pathfinding, dynamic rubberbanding, stuck-recovery state machines, or relative waypoint filtering.
- **RECOMMENDATION**:
  - **Rubberbanding**: Implement dynamic speed scaling $v_{\text{pursuer}} = \text{clamp}(v_{\text{target}} \times 1.05, 9.0, 16.0)$ when distance > 10.0m to maintain pursuit tension.
  - **Detour Routing**: Filter detour waypoints so Pursuer only targets waypoints ahead of its current position ($z_{\text{waypoint}} > z_{\text{pursuer}}$).
  - **Collision Recovery**: Add stuck detection: if `velocity.length() < 1.0` while `is_active` for > 0.4s, execute a 0.5s reverse-and-steer recovery impulse.

### Focus Area 4: Identity Assessment (Generic Sci-Fi vs Distinct Echos Design)
- **OBSERVED**:
  - Mechanics & Flow: Tactile radio tuning, physical panel peeling, energy core extraction, vehicle mounting, and gate trap counterplay create a distinct, memorable micro-play loop.
  - Visual Assets: Scene environment utilizes basic Godot primitive meshes (`MeshInstance3D` boxes, cylinders, grey floor grid) with cyan (`Color(0.1, 0.9, 1.0)`) and amber emissive accents. Visual texture layering is at greybox level.
  - Audio Texture: Analog radio hum pitch shifting, panel peel friction SFX, spark effects, bike engine pitch, and 3D siren audio give strong physical texture, though HUD UI visual language lacks diegetic sci-fi lore elements.
- **PLAYER_REACTION**:
  - `"The gameplay mechanics—tuning the frequency, pulling the core, driving the bike, slamming the gate—are actually really neat and tactile! But visually, it looks like a grey box prototype asset flip. It needs dirt, rust, scrap particles, neon signage, and stylized sci-fi HUD elements to feel like a real world instead of a Unity/Godot template."`
- **INFERENCE**:
  - Core interaction loop proves distinct identity in mechanical feel and tactile interaction, but visual surface presentation suffers from raw prototype greybox optics (`S1`/`S2` identity gap).
- **RECOMMENDATION**:
  - Apply scrap-metal texture maps, rust decals, dust/spark environmental particle systems, stylized CRT scanline UI shaders, and custom 3D vehicle/character models to elevate visual presentation to match the distinct mechanical identity.
